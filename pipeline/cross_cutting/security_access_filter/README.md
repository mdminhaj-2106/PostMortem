# Cross-Cutting Service — Security & Access Filter

**Job:** row/column/domain-level gating on what data and output a given user is shown. Applied at Stage 10's output, before narration (Stage 11) reaches anyone.

**Status:** Named in the locked topology; not yet designed. No design report exists yet.

**Reference:** [`docs/00-brief-and-topology/round2-topology-and-brief.md`](../../../docs/00-brief-and-topology/round2-topology-and-brief.md) §4 — listed as one of the 5 cross-cutting services, and flagged in §2's gap-check as entirely missing from the Round 1 architecture (one of the graded requirements — "operate within security... constraints" — that Round 2 adds).

**Deliberately distinct from Decision Rights:** Security answers "who can see this," Decision Rights answers "who can act on this." Seeing ≠ acting — the two are kept separate on purpose, not merged.
